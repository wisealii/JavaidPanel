# نصب JavaidPanel — مقایسه و وضعیت فعلی

## تجربهٔ هدف: مشابه NX Panel

مسیر نصب مطلوب پس از تکمیل واقعی هسته:

1. نصب سرور مرکزی با **یک دستور و بدون پرسش تعاملی**.
2. چاپ یک لینک راه‌اندازی **یک‌بارمصرف و کوتاه‌عمر**.
3. ویزارد وب برای ساخت اولین مدیر، انتخاب دامنه و پورت و انتخاب گواهی HTTPS.
4. مدیریت و صدور گواهی (ACME/Let's Encrypt، وارد کردن گواهی، و گواهی خودامضا صرفاً برای شروع).
5. ساخت نود در پنل و صدور دستور نصب **یک‌بارمصرف** با تأیید هویت معتبر.
6. نمایش آنلاین/آفلاین و همگام‌سازی امن پس از اتصال نود.
7. ابزار CLI برای وضعیت، به‌روزرسانی، پشتیبان‌گیری، بازیابی و حذف نصب.

این **طرح هدف** است، نه شرح قابلیت آمادهٔ نسخه فعلی.

## وضعیت واقعی نسخه 1.1.102-dev

بازبینی فایل‌های قبلی مخزن مشخص کرد که:
- `install.sh` پیشین کانتینر `node:22-alpine` را با `sleep infinity` اجرا می‌کرد.
- `node-agent-install.sh` نیز کانتینر `alpine:latest` را با `sleep infinity` اجرا می‌کرد.
- بنابراین پیام «نصب کامل» و «نود متصل شد» قابل اتکا نبود.
- فایل‌های جایگزین فعلی **عمداً از نصب ساختگی جلوگیری می‌کنند**؛ اما به معنی نصب کامل پنل نیستند.

## دستورات بی‌خطر امروز

```bash
git clone https://github.com/wisealii/JavaidPanel.git
cd JavaidPanel
bash -n install.sh
sudo bash install.sh --doctor
bash node-agent-install.sh --check
```

## صدور واقعی گواهی TLS مستقل از پنل

اگر دامنهٔ شما به IP سرور اشاره می‌کند، Certbot نصب است و پورت ۸۰ برای درخواست HTTP-01 آزاد و در دسترس است:

```bash
sudo bash install.sh --ssl panel.example.org
```

این فرمان فقط از Let's Encrypt گواهی دریافت می‌کند. **تا زمانی که وب‌سرور و هسته واقعی وجود نداشته باشد، HTTPS پنل فعال نمی‌شود.** برای تمدید معمول، Certbot از روش استاندارد خود استفاده می‌کند و در زمان استقرار واقعی باید hook بارگذاری مجدد وب‌سرور تعریف شود.

> اجرا کردن `sudo bash install.sh --install` در این نسخه عمداً خطا می‌دهد تا VPS را با یک نصب نمایشی تغییر ندهد.

## مقایسه با پنل‌های مرجع

| مرحله | NX Panel | PasarGuard | JavaidPanel فعلی |
|---|---|---|---|
| نصب | یک دستور، بدون پرسش | اسکریپت نصب | دستورات preflight و TLS؛ نصب کامل مسدود |
| ورود اولیه | لینک یک‌بارمصرف و ویزارد | تنظیمات پس از نصب | نیازمند ساخت backend |
| SSL | مدیریت گواهی در پنل | گواهی دامنه و HTTPS | اخذ مستقل با Certbot |
| نود | توکن یک‌بارمصرف یا نصب از طریق SSH | نصب عامل با اسکریپت | نصب عامل تا وجود daemon واقعی مسدود |
| به‌روزرسانی | نصب مجدد/CLI | ابزارهای نصب | نیازمند پیاده‌سازی |
| کنترل سرویس | CLI و systemd | ابزارهای کانتینری/سرویسی | نیازمند پیاده‌سازی |

## قبل از نسخه پایدار

- هستهٔ واقعی و سرویس systemd/Docker که پاسخ سلامت معتبر بدهد
- ویزارد setup امن و یک‌بارمصرف با ذخیرهٔ اتمیک
- احراز هویت، پایگاه داده، مدیریت کاربران و سرویس VPN
- مدیریت گواهی، renewal hooks، مسیر ریکاوری
- پروتکل enrollment و daemon نود با mTLS
- تست Ubuntu 20.04، 22.04، 24.04 و 26.04 (هرکدام جدا)
- بکاپ، rollback و تست upgrade روی VPS آزمایشی
