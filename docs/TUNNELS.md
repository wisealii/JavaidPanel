# تونل‌ها در JavaidPanel

**توجه:** این سند کاتالوگ فناوری و نقشهٔ آداپترهاست؛ نام روش در این صفحه یعنی «قابل بررسی»، نه «آماده کار».

## چرا تونل؟

تونل سروربه‌سرور مسیر انتقال بسته یا اتصال را بین دو VPS برقرار می‌کند. روش مناسب به TCP/UDP، MTU، NAT، امنیت، کارایی و محدودیت شبکه بستگی دارد. JavaidPanel برای هر روش باید تنظیمات، نصب دوطرفه، سلامت، حذف و بازیابی مستقل داشته باشد.

| روش | لایه/کاربرد معمول | وضعیت JavaidPanel |
|---|---|---|
| WireGuard Site-to-Site | L3 / تونل رمزگذاری‌شده | کد مقدماتی در بسته‌های توسعه؛ به نسخه main متصل نشده |
| GRE / IPIP | L3 / تونل IP | برنامهٔ توسعه؛ نیازمند رمزگذاری جداگانه |
| VXLAN | L2 overlay روی UDP | برنامهٔ توسعه |
| SSH Reverse / Local Forward | انتقال TCP | برنامهٔ توسعه |
| Rathole | relay/reverse tunnel | برنامهٔ توسعه؛ نیازمند بررسی لایسنس و نسخه |
| Backhaul | reverse/relay | برنامهٔ توسعه؛ نیازمند بررسی لایسنس و نسخه |
| OpenVPN Site-to-Site | VPN رمزگذاری‌شده | برنامهٔ توسعه |
| gRPC transport | transport اپلیکیشنی | برنامهٔ توسعه؛ به‌تنهایی «VPN پروتکل» نیست |
| Hysteria2 / TUIC | روش‌های انتقال/پروکسی | به adapter و core سازگار نیاز دارد |

## معیار «آماده»

- نصب‌کنندهٔ هر دو سمت با اعتبارسنجی IP، پورت و CIDR
- بررسی dependency/version/sha256
- نگهداری کلیدها با سطح دسترسی محدود
- بررسی firewall، route، MTU و برخورد port
- نصب مجدد idempotent، حذف کامل و rollback
- تست اتصال، قطع و وصل، reboot و احراز هویت روی دو VPS
- گزارش وضعیت و health واقعی در پنل
- هشدار درباره خطرهای GRE/IPIP بدون رمزگذاری
