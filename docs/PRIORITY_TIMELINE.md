# تایم‌لاین اولویت‌دار توسعه JavaidPanel

**مبنای بررسی:** مخزن `wisealii/JavaidPanel`، شاخه `main`، نسخه توسعه‌ای `1.1.109-dev`. این ترتیب، **اولویت و وابستگی فنی** را نشان می‌دهد، نه تعهد زمانی یا ادعای توسعه خودکار در پس‌زمینه.

هدف اول: **یک نصب موفق، بازتولیدپذیر و قابل بازیابی روی VPS آزمایشی، با SSL معتبر و حساب مدیر**. هدف دوم: اتصال نود واقعی به کنترلر، سپس پروتکل‌ها و تونل‌های بیشتر.

## نمایش فشرده مسیر

```text
[ P0 / پیش‌نیاز نصب ] ──────────────────────────────────────────────────
   بررسی نصب‌کننده و dependencies  →  bootstrap واقعی VPS
     →  حساب مدیر / دیتابیس  →  SSL و HTTPS  →  health + reboot
     →  بکاپ و بازیابی آزمایشی  →  نصب تکرارپذیر

[ P1 / حداقل بهره‌برداری ] ────────────────────────────────────────────
   حساب‌ها و RBAC  →  Javid Node + API  →  ثبت نود دوم
     →  heartbeat و ابطال کلید  →  پشتیبانی پروتکل‌های موجود

[ P2 / توسعه قابلیت‌ها ] ──────────────────────────────────────────────
   مانیتورینگ، سهمیه، کاربران و تیکت  →  WireGuard Site-to-Site
     →  آداپتر تونل‌های اصلی با rollback و تست دو سرور

[ P3 / تکمیل محصول ] ─────────────────────────────────────────────────
   داشبورد پیشرفته و تم‌ها  →  فروشگاه، گزارش‌ها و پرداخت
     →  تونل‌های تخصصی و پروتکل‌های بیشتر  →  بهینه‌سازی UX
```

## ترتیب توسعه که نباید جابه‌جا شود

1. **هر مشکل P0 که در تست قابل بازتولید است** باید با یک PR مستقل و تست رگرسیون اصلاح شود.
2. سپس یک **VPS آزمایشی تازه** برای تست installer، SSL، حساب مدیر و recovery لازم است.
3. بعد API نود و عامل روی **دو VPS واقعی** با گواهی معتبر آزمایش شوند.
4. فقط پروتکل‌هایی را در UI «پشتیبانی‌شده» بنویسیم که با کلاینت واقعی تست اتصال/قطع و ترافیک دارند.
5. تازه بعد از این گیت‌ها، توسعه آداپترهای متنوع، فروشگاه، UX و امکانات P2/P3 جلو برود.

## گیت‌های کیفیت و شواهد

- `bash install.sh --self-test` و آزمون‌های CI باید موفق باشند.
- `python3 tools/release-readiness.py --strict` **تا زمان وجود شواهد واقعی باید ناموفق بماند**.
- هر فاز باید: کد روی GitHub، تست خودکار، گزارش خطا و نمونه اجرا با اطلاعات حذف‌شده از رازها داشته باشد.
- عبور از گیت VPS فقط با ذکر **OS و نسخه، معماری، مشخصات آزمایش، نتیجه SSL، ورود، نود، بکاپ و rollback** پذیرفته می‌شود.
- **تایم‌لاین، وعده فعالیت در هنگام بسته‌بودن گفتگو نیست**؛ پیشرفت هر مرحله بعد از اجرای کار/آزمون همان مرحله ثبت می‌شود.

## خروجی این تغییر

در نسخه `1.1.109-dev`، مسیر SSL هنگام نبود DNS یا ناممکن‌بودن بررسی پورت fail-closed می‌شود و سناریوهای IPv4/IPv6/خطا تست آفلاین دارند. این فقط یک گام P0 است، نه پایان مرحله P0.
