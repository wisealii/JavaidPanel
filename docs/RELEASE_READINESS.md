# آزمون آمادگی نصب JavaidPanel روی VPS

نسخه توسعه‌ای **1.1.108-dev**. این ابزار صرفاً یک گزارش قابل تکرار از وضعیت کد و شواهد است. اجرای موفق آزمون GitHub Actions **به معنی آمادگی نصب یا تأیید VPN نیست**.

## ۱. بررسی ایستا از روی سورس

```bash
git clone https://github.com/wisealii/JavaidPanel.git
cd JavaidPanel
python3 tools/release-readiness.py
```

برای دریافت خروجی ساختاریافته:

```bash
python3 tools/release-readiness.py --json
```

برای **ممانعت از انتشار نهایی** تا رفع همه موانع:

```bash
python3 tools/release-readiness.py --strict
```

در این نسخه حالت strict باید خروجی غیرصفر بدهد، چون تست واقعی VPS، SSL، اتصال دو نود، پروتکل‌ها و بازیابی انجام نشده است.

## ۲. پیش‌نیازهای مهم

- یکی‌بودن نسخهٔ پروژه و نسخه اعلام‌شده در `install.sh`
- تطابق هش SHA-256 هسته نصب
- صحت نحوی تمام اسکریپت‌های Bash
- بررسی فایل‌های ضروری Javid Node/API
- تشخیص روش استقرار Docker Compose ناقص
- بررسی دستی نصب و حساب مدیر، SSL واقعی، نودهای دو سروره و پروتکل‌های عملیاتی

## ۳. عیب مشخص فعلی

`docker-compose.production.yml` دارای ارجاع به `Dockerfile` و `nginx/nginx.conf` است، اما این فایل‌ها هنوز در مخزن موجود نیستند. **مسیر Docker Compose در حال حاضر قابل استقرار نیست** و نباید به‌عنوان گزینه آماده به کاربران پیشنهاد شود.

مسیر اصلی نصب، اسکریپت پین‌شده `install.sh` است؛ این مسیر نیز هنوز به تست عملی VPS نیاز دارد.

## ۴. چک‌لیست آزمون واقعی

بعد از تهیه یک VPS آزمایشی تازه و ثبت نسخه OS/CPU:

1. اجرای `--doctor` و بررسی فضای دیسک، RAM، پورت‌ها.
2. اجرای نصب با یک فرمان؛ ثبت لاگ **بدون رمز، توکن و کلید**.
3. تأیید ساخت دیتابیس، ورود مدیر و باقی‌ماندن اطلاعات پس از reboot.
4. دریافت گواهی Let's Encrypt روی دامنه کنترل‌شده و تأیید HTTPS از مرورگر.
5. ثبت نود دوم، دریافت heartbeat، انقضا و ابطال توکن.
6. آزمایش اتصال و ترافیک واقعی هر پروتکل معرفی‌شده.
7. بکاپ‌گیری و بازیابی روی نمونه دیگر، سپس آزمون ارتقا و rollback.

تا انجام‌نشدن این آزمون‌ها، گزارش `--strict` نباید موفق شود.
