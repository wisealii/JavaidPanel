# ممیزی کامل امکانات موجود JavaidPanel تا مرز نصب VPS

**نسخه فعلی سورس در زمان بازبینی این سند:** `1.1.113-dev` · **مبنای ممیزی اولیه:** `1.1.111-dev` · **نوع شواهد:** بررسی سورس و تست محلی/CI؛ هنوز هیچ نصب واقعی VPS در این مرحله تأیید نشده است.

**تفسیر وضعیت‌ها:** در `docs/CURRENT_FEATURES.json` تعداد ۲۲ قابلیت ثبت شده است: ۹ مورد با برچسب `offline_tested` و ۱۳ مورد با برچسب `source_only`. این برچسب‌ها فقط سطح شواهد ثبت‌شده را نشان می‌دهند؛ به معنای تأیید عملیاتی قابلیت یا درصد آمادگی VPS نیستند. برای دسترسی‌ها، مسیرهای Gateway و API مستقل نود باید جداگانه بررسی شوند؛ وجود توکن مدیر در API نود به معنای وجود RBAC چهارسطحی نیست.

## دامنه پروژه در این مرحله

فقط اجزایی بررسی و برای نصب آماده‌سازی می‌شوند که همین حالا در شاخه اصلی JavaidPanel فایل یا کد پیاده‌سازی دارند. ساخت پروتکل جدید، فروشگاه، پنل تجاری یا آداپتر تونل جدید **خارج از این مرحله** است.

فهرست ساختاریافته با شاهد هر قابلیت در [CURRENT_FEATURES.json](CURRENT_FEATURES.json) است. ابزار [audit-current-features.py](../tools/audit-current-features.py) وجود مسیرها و نشانه‌های سورس را کنترل می‌کند. این کنترل **قابلیت عملیاتی را اثبات نمی‌کند**.

## لایه ۱ — هسته نصب یک‌دستوری (در مسیر اصلی install.sh)

| قابلیت موجود در سورس | فایل / نشانه | وضعیت و ریسک |
|---|---|---|
| بوت‌استرپ با SHA-256 و preflight | `install.sh`، `CORE_SHA256` | بررسی ایستا؛ اجرای کامل VPS نامعلوم |
| معماری و OS، RAM و دیسک | `install.sh`، `--doctor` | شرایط x86_64 و Ubuntu 24.04 / Debian 12/13 در کد تعریف شده؛ هنوز روی سرور هدف آزمایش نشده |
| انتخاب دامنه، IP، حالت SSL و پورت | `installer/core.sh`، `ALIREZA_TLS_MODE` | ویزارد تعاملی موجود؛ صدور واقعی گواهی و دسترسی بیرونی هنوز آزمایش نشده |
| دریافت و تمدید Let's Encrypt | `installer/core.sh`، `tls.py` و timer تمدید | در کد وجود دارد؛ تست ACME و renewal روی دامنه واقعی الزامی |
| ایجاد و تغییر رمز مدیر | `installer/core.sh`، `manage.py` | ساخت و reset در سورس وجود دارد؛ ورود و کنترل نشست روی VPS باید آزموده شود |
| VPN backend و دیتابیس | `installer/core.sh`، `VPN_SHA` و `seed_vpn` | binary خارجی با هش پین‌شده دانلود می‌شود؛ تست اتصال/قطع واقعی ندارد |
| DNS backend و UI | `installer/core.sh`، `AGH_SHA` | binary خارجی پین‌شده، سرویس و رابط تعریف شده؛ تست DNS از کلاینت ندارد |
| Gateway، جلسات و ناوبری | `gateway.py` در embedded core | کد اجرای Gateway دارد؛ آزمون HTTP/Session و محافظت مسیرها روی VPS الزامی است |
| نودهای پایه و گزارش‌ها | `nodes.py`, `insights.py`, `dns_clients.py`, `features.py` | کدهای embedded وجود دارند، اما تست نصب چندسروری/داده زنده تأیید نشده |
| سلامت، restart و repair | CLI تولیدشده توسط core + `manage.py` | دستورها در کد وجود دارند؛ آزمایش خرابی و بازیابی لازم است |
| backup دستی | فرمان `backup` در CLI embedded | صرفاً بکاپ‌گیری تعریف شده؛ restore قابل اتکای کامل در مسیر اصلی تأیید نشده |

این امکانات یک مسیر نصب واحد را تعریف می‌کنند، اما **موفقیت نصب واقعی و صحت موتورهای VPN هنوز اثبات نشده است**.

## لایه ۲ — افزونه‌های موجود که با نصب اصلی یک‌دستوری نصب نمی‌شوند

| جزء | وضعیت واقعی |
|---|---|
| API کنترلر Javid Node | کد HTTP/API، توکن زمان‌دار و claim وجود دارد؛ تست محلی دارد |
| Agent Javid Node | سرویس heartbeat امضاشده و نصب‌کننده جداگانه دارد؛ روی دو VPS تست نشده |
| داشبورد خصوصی نود | از loopback و SSH Tunnel قابل استفاده طراحی شده؛ با حساب مدیر Gateway یکپارچه نیست |
| ارتقای کنترلر نود | ابزار plan/upgrade و rollback سورس دارد؛ تست فایل‌سیستم موقت و نه VPS |
| ابزار SSL ترمینالی | وجود دارد؛ جایگزین تنظیم HTTPS سرویس پایه نیست |
| آزمون‌های آفلاین و گیت انتشار | GitHub Actions و readiness موجود؛ شواهد عملی VPS تولید نمی‌کنند |

**اصل مهم:** نصب `install.sh` به‌تنهایی Javid Node جدید، dashboard نود مستقل و API آن را نصب نمی‌کند. تا ادغام آزمایش‌شده، آن‌ها باید جداگانه و در سطح توسعه‌ای معرفی شوند.

## محدودیت‌های کنونی که مانع عنوان «نصب تأییدشده» می‌شوند

1. **نصب بدون TTY** در کد قبلی می‌توانست ناخواسته به HTTPS خودامضاشده IP پیش‌فرض برود. نسخه 1.1.111-dev این حالت را بدون انتخاب صریح mode رد می‌کند.
2. هنوز گزارش نصب تمیز روی VPS واقعی همراه با خروجی HTTP(S)، ورود مدیر و log بدون اسرار نداریم.
3. تست دامنه واقعی/گواهی معتبر و تمدید خودکار ثبت نشده است.
4. restore واقعی دیتابیس و تنظیمات روی سرور جایگزین تست نشده است.
5. مسیر Gateway اصلی و API مستقل Javid Node احراز هویت مشترکِ تست‌شده ندارند.
6. نصب پایه و API نود جدا هستند؛ راه‌اندازی نود دوم با یک دستور باید در آزمون جدا سنجیده شود.
7. پایداری VPN و DNS و پروتکل‌ها با کلاینت بیرونی، قطع و وصل، reboot و میزان ترافیک آزموده نشده است.

## سناریو پذیرش برای VPS آزمایشی

| آزمون | شرط قبولی و مدرک |
|---|---|
| پیش‌نیازها | `--doctor` با نسخه OS/CPU/RAM/دیسک و نبود تعارض سرویس |
| نصب با دامنه | صدور ACME واقعی، DNS صحیح و HTTP(S) معتبر از خارج VPS |
| مدیر | ساخت رمز قوی، ورود، خروج، reset و ورود مجدد؛ بدون افشای رمز در log |
| ذخیره‌سازی | ساخت دیتابیس، تغییر داده و حفظ آن پس از reboot |
| وضعیت سرویس | systemd units فعال، healthcheck، Gateway و DNS قابل دسترس |
| بکاپ/بازیابی | restore واقعی داده روی محیط جدا، بررسی ACL و محرمانگی کلیدها |
| VPN | ایجاد پیکربندی و اتصال کلاینت واقعی، اندازه‌گیری ترافیک و قطع/وصل |
| نگهداری | repair و restart بدون حذف اطلاعات و با بازگشت از شکست |

برای کمک به خروجی شفاف، گیت انتشار باید تا تکمیل شواهد واقعی **مسدود باقی بماند**. نتیجه `python3 tools/release-readiness.py --strict` عمداً هنوز نباید 0 باشد.

## دستورهای تست بدون نصب

```bash
bash -n install.sh
bash install.sh --self-test
python3 tools/audit-current-features.py
python3 -m unittest discover -s tests -p 'test_current_features_audit.py' -v
python3 tools/release-readiness.py
```

## مسیر نصب برای آزمایش بعد از تهیه VPS

پس از بازبینی کد و تهیه VPS تازه، به‌صورت تعاملی یک حالت دسترسی مشخص (ترجیحاً دامنه + SSL معتبر) انتخاب می‌شود. اگر نصب اتوماتیک بدون ترمینال است، باید TLS mode و host صریحاً تعیین شوند؛ نصب بدون این ورودی‌ها نباید خودسرانه به گواهی خودامضاشده برود.

در پایان تنها پس از بررسی سرویس، SSL، ورود، backup و اتصال کلاینت روی VPS می‌توان این نصب را «تأییدشده برای VPS آزمایشی» نامید. تا قبل از آن نسخه **development** است.
